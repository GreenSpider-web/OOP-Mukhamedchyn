# Звіт до самостійної роботи №2
**Тема:** Перевантаження конструкторів: приклади та сценарії

## 1. Реалізований клас `Product`
* Приватні `readonly` поля `_id`, `_name`, `_price`, `_category` і `_stockCount` зберігають характеристики товару. Публічні властивості доступні лише для читання.
* **Основний конструктор** отримує повний набір характеристик товару.
* **Скорочений конструктор** приймає `id`, `name` і `price`, а через `this(...)` встановлює категорію `"Uncategorized"` та залишок `0`.
* **Конструктор копіювання** приймає інший `Product` і передає його дані до основного конструктора через `this(...)`.
* Перевизначений `ToString()` формує рядок із детальним описом товару.

## 2. Перевірка роботи
* У `Main` створюються товар із повними параметрами, товар зі скороченими даними та копія першого об'єкта.
* Дані всіх трьох об'єктів виводяться в консоль із зазначенням відповідного конструктора.

## 3. Відповіді на контрольні запитання
1. **Навіщо потрібне перевантаження конструкторів у класі `Product`?**
   Воно дає змогу створювати об'єкти товару, маючи різну кількість початкових даних.
2. **Чому конструктор копіювання зручно реалізовувати через `this(...)`?**
   Такий підхід повторно використовує головний конструктор і не дублює код ініціалізації.
3. **Які переваги має read-only доступ до властивостей?**
   Після створення об'єкта його характеристики не можна змінити через публічний інтерфейс.
4. **Коли перевизначення `ToString()` спрощує налагодження та демонстрацію?**
   Воно корисне, коли стан об'єкта потрібно швидко представити у зрозумілому текстовому вигляді, наприклад у консолі або журналі.
