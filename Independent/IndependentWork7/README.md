# Звіт до самостійної роботи №7
**Тема:** Узагальнений кеш Cache<TKey, TValue> із тестами (FIFO)

## 1. Реалізація політики FIFO
Узагальнений клас `Cache<TKey, TValue>` використовує дві структури даних:
* `Dictionary<TKey, TValue>` — для забезпечення пошуку та доступу до значень за ключем за час O(1).
* `Queue<TKey>` — для відстеження точного порядку додавання ключів (First In, First Out).

При досягненні граничної ємності (`_capacity`) виклик `Add` вилучає найстаріший ключ з голови черги за допомогою `_keysOrder.Dequeue()` і видаляє відповідний запис зі словника `_cache.Remove(oldestKey)`.

## 2. Відповіді на контрольні запитання

1. **Які переваги надає Cache<TKey, TValue> порівняно з окремими неузагальненими реалізаціями кешу?**
   * **Строга типізація (Type Safety):** більшість помилок виявляється ще під час компіляції.
   * **Продуктивність:** для значущих типів не потрібні зайві операції boxing/unboxing.
   * **Універсальність:** один клас працює з різними типами ключів і значень без копіювання реалізації.

2. **Чому для реалізації політики FIFO зручно поєднувати Dictionary<TKey, TValue> з Queue<TKey> або LinkedList<TKey>?**
   * `Dictionary` швидко знаходить значення за ключем у середньому за O(1).
   * `Queue` зберігає порядок FIFO і дає змогу вилучити найстаріший ключ за O(1), не переглядаючи весь кеш.

3. **У яких випадках метод Get повинен викидати KeyNotFoundException, а коли доцільніше використовувати підхід на кшталт TryGetValue?**
   * `KeyNotFoundException` доречний, якщо відсутній ключ означає помилку або порушення очікуваного контракту.
   * `TryGetValue` краще застосовувати, коли cache miss є звичайним сценарієм і не варто використовувати винятки для керування потоком.

4. **Які тести є критично важливими для перевірки політики витіснення елементів з кешу?**
   * Потрібно перевірити, що після додавання N+1 елемента вилучається саме ключ, доданий першим.
   * Варто перевірити правильність `Count` після витіснення.
   * Слід перевірити звернення до вилученого ключа: `ContainsKey` має повернути `false`, а `Get` — передбачену контрактом помилку.
